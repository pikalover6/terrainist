**One thing needs live confirmation when the Mac is awake:** the pinned
`TRIPO_MODEL_VERSION = "v3.0-20250812"` in `tripo-config.ts`. The spec says
`"tripo-v3"`, which is not a wire value, so the pin follows Tripo's
`vN.N-YYYYMMDD` convention as a best guess. **No test can catch a wrong
pin** — Tripo publishes no model-catalog endpoint to diff against (unlike
OpenRouter's `verifyModelAvailable`). `verifyTripoAvailable` does a
credential/reachability check against `/user/balance` and reports the pin
plus the file to edit; the first real API call is the actual verification.
Everything else in the client is pin-agnostic.

**Critical correction to a doc claim:** `docs/DESIGN.md` L104-106 says "the
`asset` node kind is in the schema from v0 … the interface exists from day
one". That is **true of the spec document only, not of the implementation** —
`grep '"asset"'` over `packages/*/src` returns zero hits, and both validators
accept only `composite` roots plus `generator` children
(`packages/spec/src/terrain/validate.ts:375`,
`packages/spec/src/settlement/validate.ts:164`). The node type must be
**built, not extended**. Also: `packages/render/src/voxel/` is a *renderer*
(canvas/isometric/png), **not** a mesh voxelizer — do not mistake it for
scaffolding.

Normative spec: `docs/LOAM-SPEC-v0.2.md` §9 (L2955-3230) — node shape
§9.1 L2961-3007, params §9.2, deterministic prompt augmentation §9.3, roles
§9.4, shell interiors §9.5, fallback + `LOAM-W301/W302` §9.7, **the asset
lockfile §9.8 L3119-3161** (the determinism answer), voxelization §9.9.
