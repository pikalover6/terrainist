## The harness (critical, non-obvious)

This project runs on a **patched Claude Code** (patch:
https://github.com/pikalover6/claude-subagents-effort, authored by Opus 5).
The patch adds the Agent tool's `effort` parameter — vanilla Claude Code
cannot set subagent reasoning effort (YAML agent `effort` frontmatter is
believed broken; GitHub issues + Kai's empirical results agree). Workflow:
Fable 5 high orchestrates; Opus 5 LOW implements; Opus 5 high only for
design/spec/meta work. The patch edits the npm package's bundled cli.js
(plain JS ⇒ architecture-independent, arm64 OK) and is pinned to a Claude
Code version — verify on every CC update.

Claude Code Cloud is ruled out: can't run the patch there, and Kai could not
join remote-control sessions started in it (auth differences).

## Cloud plan (sequential)

Target: patched Claude Code running 24/7 on an Oracle free-tier ARM box,
supervised from Kai's Claude desktop app via remote control, exchanging work
with Kai's laptop through GitHub.

1. **Repo push (local, first):** remote is https://github.com/pikalover6/terrainist
   (private). `gh auth status` → `git remote add origin … && git push -u origin main`.
2. **Patch update (dedicated Opus 5 HIGH subagent, per Kai):** clone the patch
   repo; adapt to the current Claude Code release; ADD the QoL change Kai
   wants: subagent display name set internally (not render-side) to
   model+effort, e.g. `opus-5-low` instead of `general-purpose`, so the
   vanilla desktop client shows it. Deliver an idempotent `apply-patch.sh`
   (download pinned vanilla CC → verify version → patch cli.js → smoke test)
   so no patched binary is ever distributed.
3. **Box provisioning (Kai, with walkthrough):** Oracle Always Free
   VM.Standard.A1.Flex (4 OCPU / 24 GB, Ubuntu 24.04 aarch64; capacity varies
   by region). Only inbound SSH (22). Kai sends: public IP + ssh user + key.
4. **Box bootstrap (agent via ssh):** node 22 + git + gh + tmux (+ optional
   tailscale); install vanilla Claude Code at the pinned version; run
   apply-patch.sh; `claude setup-token` for headless auth (Kai pastes the
   token); clone repo; `.env` with OPENROUTER_API_KEY (+ TRIPO key when Kai
   sends it — still pending); `npm ci && npm run build && npm test` (expect
   1075 green). Run sessions inside tmux with remote control enabled.
5. **Test checklist before real work:** (a) effort respected — patch repo's
   own verification method, plus token-usage comparison of an identical task
   at low vs high; (b) Kai can join the session from the desktop app; (c)
   subagent names render as `opus-5-low` etc.; (d) full suite green on arm64;
   (e) one end-to-end: box commits a trivial change → laptop pulls, compiles,
   installs a world.
6. **Laptop bridge — git, not file transfer:** worlds are byte-deterministic
   from (commit, doc, seed), so the box ships commits, never region files.
   Laptop side: pull → `terrainist compile/devworld/terrarium` → `install
   --replace` (seconds). Feedback path: `review-import` session JSON +
   referenced screenshots committed to `feedback/<date>/` on a branch or
   main; the cloud session treats that directory as its inbox. GLM-authored
   docs are small JSONs — commit them too. Optional: Tailscale for direct
   SSH/remote control of a small local session; NOT required for the loop.
   No inbound access to the laptop is needed in the base design.
7. **Concurrency/plan caution:** box sessions share Kai's subscription
   limits with local sessions; don't run heavy fleets in both places at once.
