puzzle — `sonnet-5-low` spent 3 output tokens (wrong answer), `sonnet-5-xhigh`
spent 3,994 (correct); `max` reaches the wire unclamped on opus and sonnet;
parent stays at its own effort throughout. The old "frontmatter effort is
broken" belief was a stack of SILENT traps, not a missing feature:
(1) frontmatter `name:` is MANDATORY — filename is not a fallback; without
it the definition is silently ignored and dispatch falls back to built-ins;
(2) integer efforts silently send no output_config (named levels only);
(3) definitions are cached at session start, so mid-session edits are no-ops.
All three are guarded by `packages/spec/test/agent-defs.test.ts`. The repo
ships a generic 15-type matrix (`opus|fable|sonnet-5-{low,…,max}`);
dispatch by `subagent_type` to get effort control on stock. `claude -p
--effort <level>` also works on stock for headless workers. Note: stock
records the agent type name (not effort) in subagent meta.json — the
model+effort naming convention is what surfaces effort in UIs/metadata.

Kai's local harness additionally carries the patch
(https://github.com/pikalover6/claude-subagents-effort, authored by Opus 5),
which adds the one thing stock lacks: a per-invocation `effort` param on the
Agent tool. It still applies cleanly to 2.1.220 (dry-run verified) but is a
convenience, not a dependency — **new machines need stock CC + this repo,
no patch**. After CC updates, re-run the probe before trusting
effort-sensitive workflows.
